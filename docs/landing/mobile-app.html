Why this is worth carrying

“Do not build a pipeline.” It built a pipeline.

Given a command-line-tool specification in a clean, contamination-checked workspace — with an explicit instruction forbidding pipeline output — a leading agent shipped a data-pipeline application instead. Confirmed by reading the code. Every functional test would have passed it: the wrong product, built well. That is the class of risk no benchmark reports and no green CI badge reveals — and it is what this instrument exists to catch.

How it works

The engine measures. The phone reports.

Evaluations run where static analysis belongs — on a machine with a filesystem and a toolchain. The app is the client that puts the resulting evidence in your hand.

STEP 01

One fixed specification

The same versioned brief goes to every candidate tool — and to a human reference. Nothing is compared unless it was produced under identical conditions.

STEP 02

Five analysers score it

Security, complexity, duplication, scope drift and rework — each its own deterministic, version-pinned analyser, blind to which tool produced the code.

STEP 03

Evidence in your pocket

Results publish to the dashboard API; the app reads them over HTTPS and renders the report — same numbers, same thresholds, same provenance, on the device you already carry.

Stated plainly

What the app does not do

It does not run the analysers on your phone. They shell out to static analysis tools and walk a filesystem, which no mobile sandbox permits — so the app is a reporting client, not the engine. It collects no personal data, has no accounts, no analytics and no advertising identifiers; it makes anonymous read-only requests to the evaluation API.

We say this here for the same reason the instrument reports its own blind spots: an assurance product that overstates itself has already failed its own test.
